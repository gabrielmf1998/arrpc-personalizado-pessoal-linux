O QUE E ISSO
------------
Um daemon em Python que faz o Discord mostrar jogos e apps que ele nao
detecta sozinho no Linux. Ele procura os processos e fala o protocolo
IPC do Discord direto, publicando a Rich Presence.

Requisitos: systemd (servico de usuario), python3, ss (iproute2),
busctl (systemd, para apps de midia) e um cliente Discord que exponha
o socket de IPC - Vesktop nativo.

 PARTE 1 - INSTALACAO

--------------------------------------------------------------------
PASSO 1 - DEPENDENCIAS
--------------------------------------------------------------------
Arch:
    sudo pacman -S --needed python iproute2 systemd curl

Debian / Ubuntu / Pop!_OS / Mint:
    sudo apt update
    sudo apt install python3 iproute2 curl

Fedora / Nobara:
    sudo dnf install python3 iproute curl

openSUSE:
    sudo zypper install python3 iproute2 curl


--------------------------------------------------------------------
PASSO 2 - VESKTOP NATIVO
--------------------------------------------------------------------
IMPORTANTE: nao use a versao Flatpak do Discord/Vesktop. O Flatpak roda
em sandbox com /run isolado, e o socket discord-ipc-0 nao fica visivel
para o daemon. Use pacote nativo.

Arch:
    sudo pacman -S vesktop

Debian / Ubuntu:
    1. abra https://github.com/Vencord/Vesktop/releases/latest
    2. baixe o arquivo terminado em _amd64.deb
    3. sudo apt install ./vesktop_*_amd64.deb

Fedora:
    1. baixe o arquivo terminado em .x86_64.rpm da mesma pagina
    2. sudo dnf install ./vesktop-*.x86_64.rpm

openSUSE:
    1. baixe o .x86_64.rpm
    2. sudo zypper install --allow-unsigned-rpm ./vesktop-*.x86_64.rpm

Qualquer outra distro (tarball):
    1. baixe vesktop-<versao>.tar.gz (sem sufixo de arquitetura)
    2. sudo mkdir -p /opt/Vesktop
    3. sudo tar -xzf vesktop-*.tar.gz -C /opt/Vesktop --strip-components=1
    4. sudo ln -sf /opt/Vesktop/vesktop /usr/local/bin/vesktop

Abra o Vesktop e faca login. Confirme que o socket existe:

    ls /run/user/$(id -u)/discord-ipc-0

Se esse arquivo nao aparecer, o daemon nao tem como publicar nada.


--------------------------------------------------------------------
PASSO 3 - O DAEMON
--------------------------------------------------------------------
    mkdir -p ~/.local/bin ~/.config/systemd/user
    cp discord-game-presence.py ~/.local/bin/
    chmod +x ~/.local/bin/discord-game-presence.py
    cp systemd/discord-game-presence.service ~/.config/systemd/user/

    systemctl --user daemon-reload
    systemctl --user enable --now discord-game-presence.service

Conferir:
    systemctl --user status discord-game-presence

Deve dizer "active (running)". O servico ja fica habilitado para subir
sozinho no proximo boot.

 PARTE 2 - CUSTOMIZACAO: COLOCANDO OS SEUS APPS
####################################################################

--------------------------------------------------------------------
PASSO 4 - COMO O DAEMON DECIDE O QUE MOSTRAR
--------------------------------------------------------------------
Existem duas camadas:

  a) uma tabela padrao dentro do proprio discord-game-presence.py
     (chamada GAMES), com os apps que ja vem configurados;

  b) o SEU arquivo, em:

         ~/.config/discord-game-presence.json

     que e aplicado POR CIMA da tabela padrao.

Regras da sobreposicao:
  - processo que nao existe na tabela  -> entrada nova, adicionada
  - processo que ja existe             -> so os campos citados mudam
  - client_id vazio ("")               -> desliga aquela entrada

Ou seja: para customizar, voce nunca precisa editar o Python. Cria o
JSON, reinicia o servico e pronto.

Como o daemon acha o app: ele roda, por baixo, o equivalente a

    pgrep -f "<o que voce escreveu como chave>"

Isso significa que QUALQUER pedaco da linha de comando serve. E por isso
que da certo com jogos sob Proton, cujo processo aparece com caminho do
Windows, tipo:

    S:\common\Left 4 Dead 2\left4dead2.exe

Nesse caso basta usar  left4dead2  como chave.


--------------------------------------------------------------------
PASSO 5 - ADICIONAR UM JOGO QUE EXISTE NA BASE DO DISCORD
--------------------------------------------------------------------
5.1) descubra o Application ID na base publica do Discord:

    curl -s https://discord.com/api/v9/applications/detectable > det.json
    python3 - <<'FIM'
    import json
    for a in json.load(open('det.json')):
        if 'parte do nome' in a['name'].lower():
            print(a['id'], a['name'])
    FIM

    Troque 'parte do nome' por um pedaco do nome do jogo, em minusculas.
    Ex: 'terraria', 'hollow', 'counter-strike'.

5.2) descubra como o processo aparece. Com o jogo ABERTO:

    ps aux | grep -i <nome do jogo>

    Escolha um trecho ESTAVEL da linha - de preferencia o nome do
    executavel. Evite caminhos completos e numeros de versao, que mudam.

5.3) teste o trecho escolhido antes de escrever no JSON:

    pgrep -af "<seu trecho>"

    Se nao imprimir nada, o trecho esta errado. Se imprimir varias
    linhas, tudo bem: basta uma para o daemon considerar o jogo aberto.

5.4) escreva em ~/.config/discord-game-presence.json:

{
  "games": {
    "meujogo.exe": {
      "client_id": "1234567890",
      "details": "Meu Jogo",
      "state": "Jogando",
      "large_text": "Meu Jogo"
    }
  }
}

5.5) systemctl --user restart discord-game-presence


--------------------------------------------------------------------
PASSO 6 - ADICIONAR UM APP QUALQUER (SEM ID NA BASE)
--------------------------------------------------------------------
Apps que nao sao jogos (Stremio, YouTube, VLC, Spotify alternativo,
qualquer coisa) nao existem na base do Discord. Voce cria um app seu:

    1. entre em https://discord.com/developers/applications
       (no NAVEGADOR - nao e a opcao "Modo de Teste de Aplicativos"
        que fica dentro do cliente do Discord)
    2. clique em "New Application" (canto superior direito)
    3. de o nome que deve APARECER no seu perfil. Ex: VLC
    4. aceite os termos e clique em Create
    5. em "General Information", suba uma imagem em App Icon
    6. copie o "Application ID" (numero longo)

ATENCAO: o nome exibido no Discord e o NOME DO APP que voce criou.
O campo "details" do JSON e a linha de baixo, nao o titulo.

Depois e igual ao passo 5.4: escreva a entrada com esse client_id.

Sobre a imagem: se voce nao subir Art Assets, pode usar o proprio icone
do app como imagem grande. A URL e:

    https://cdn.discordapp.com/app-icons/<APPLICATION_ID>/<ICON_HASH>.png

Para descobrir o ICON_HASH:

    curl -s https://discord.com/api/v9/applications/<APPLICATION_ID>/rpc

Procure o campo "icon" na resposta. Coloque a URL montada no campo
"large_image".


--------------------------------------------------------------------
PASSO 7 - TROCAR OS APPS DE MIDIA PELOS SEUS
--------------------------------------------------------------------
Stremio, YouTube e YouTube Music vem apontando para apps criados pelo
autor. Se voce quiser o SEU app (com o seu icone), sobrescreva so o id:

{
  "games": {
    "youtube":                 { "client_id": "SEU_ID" },
    "youtube-music":           { "client_id": "SEU_ID" },
    "libexec/stremio/stremio": { "client_id": "SEU_ID" }
  }
}

Para DESLIGAR um app que voce nao usa, deixe o id vazio:

{
  "games": {
    "rs2client": { "client_id": "" }
  }
}


--------------------------------------------------------------------
PASSO 8 - CAMPOS DISPONIVEIS, UM POR UM
--------------------------------------------------------------------
client_id    Application ID. Obrigatorio. Vazio desliga a entrada.

details      Primeira linha da presenca, embaixo do nome do app.

state        Segunda linha.

large_text   Texto que aparece ao passar o mouse na imagem grande.

large_image  Imagem grande. Aceita duas coisas:
               - o NOME de um Art Asset que voce subiu no portal, em
                 Rich Presence > Art Assets   (ex: "game")
               - uma URL de imagem
                 (ex: "https://cdn.discordapp.com/app-icons/.../x.png")

type         0 = Jogando (padrao)
             2 = Ouvindo
             3 = Assistindo
             OBS: hoje o Discord IGNORA esse campo via RPC e mostra
             tudo como "Jogando". Deixe como referencia.

running      (so no Python) funcao que decide se o app esta ativo,
             para casos em que olhar o processo nao basta - como uma
             aba de navegador.

PASSO 9 - EXEMPLOS PRONTOS
--------------------------------------------------------------------
Um jogo simples:

{
  "games": {
    "terraria": {
      "client_id": "356875570916753438",
      "details": "Terraria",
      "state": "Jogando",
      "large_text": "Terraria"
    }
  }
}

Um jogo sob Proton (repare que basta o nome do .exe):

{
  "games": {
    "eldenring.exe": {
      "client_id": "961084435603689502",
      "details": "ELDEN RING",
      "state": "Nas Terras Intermedias",
      "large_text": "ELDEN RING"
    }
  }
}

Varios de uma vez, mais desligar um que nao uso:

{
  "games": {
    "terraria":  { "client_id": "356875570916753438",
                   "details": "Terraria", "state": "Jogando",
                   "large_text": "Terraria" },
    "factorio":  { "client_id": "356878059691868160",
                   "details": "Factorio", "state": "A fabrica cresce",
                   "large_text": "Factorio" },
    "rs2client": { "client_id": "" }
  }
}

Cuidado com JSON: sem virgula sobrando no ultimo item, aspas duplas
sempre. Para validar antes de reiniciar:

    python3 -m json.tool ~/.config/discord-game-presence.json


--------------------------------------------------------------------
PASSO 10 - QUANDO O JSON NAO BASTA
--------------------------------------------------------------------
Presencas que MUDAM sozinhas (servidor do Minecraft, mapa do L4D2,
musica tocando) sao funcoes Python na tabela GAMES, dentro do arquivo
~/.local/bin/discord-game-presence.py.

Regras:
  - "details" e "state" aceitam texto OU uma funcao sem argumentos
  - a funcao de "state" pode devolver:
        "texto"                      -> so a linha
        ("texto", None)              -> igual
        ("texto", {...})             -> com extras
  - os extras aceitos no dicionario:
        "timestamps": {"start": ..., "end": ...}   tempo/progresso
        "buttons":    [{"label": "...", "url": "..."}]   ate 2 botoes
        "large_image" / "large_text"   troca a imagem a cada faixa
  - devolver uma LISTA no lugar do dicionario vira party:
        ("em servidor", [45, 1000])  -> mostra "(45 of 1000)"

Os detectores que ja existem (mc_state, l4d2_state, yt_state,
ytm_state, stremio_state) servem de modelo - copie o mais parecido.

Depois de editar o Python:
    systemctl --user restart discord-game-presence
    journalctl --user -u discord-game-presence -n 30

PASSO 11 - MAPA DO LEFT 4 DEAD 2
--------------------------------------------------------------------
O L4D2 nao publica o mapa em lugar nenhum. A unica fonte e o log do
console. Ative assim:

    1. localize a pasta do jogo, normalmente uma destas:
         ~/.local/share/Steam/steamapps/common/Left 4 Dead 2/left4dead2
         /mnt/<disco>/SteamLibrary/steamapps/common/Left 4 Dead 2/left4dead2

    2. crie ou edite o arquivo cfg/autoexec.cfg dentro dela e acrescente:
         con_logfile "console.log"

    3. FECHE E ABRA O JOGO. O log so passa a existir no proximo boot
       do jogo. Ate la a presenca mostra apenas "Jogando".


--------------------------------------------------------------------
PASSO 12 - DIAGNOSTICO
--------------------------------------------------------------------
Nao aparece nada:
    - o socket existe?      ls /run/user/$(id -u)/discord-ipc-*
    - o servico esta vivo?  systemctl --user status discord-game-presence
    - erros no log?         journalctl --user -u discord-game-presence -n 50
    - Vesktop e nativo?     flatpak list | grep -i vesktop  (nao deve achar)
    - nas configuracoes do Discord, "Status de atividade" ligado?

O app abriu mas nao detectou:
    - teste o padrao:  pgrep -af "<o que voce pos como chave>"
      se nao retorna nada, o padrao esta errado
    - o JSON e valido?  python3 -m json.tool ~/.config/discord-game-presence.json
    - o mesmo jogo pode ter processo diferente conforme o modo: L4D2
      nativo e "hl2_linux -game left4dead2", sob Proton e
      "left4dead2.exe". Use um trecho que sirva aos dois: left4dead2

Aparece como "Jogando" mesmo sendo musica ou serie:
    - limitacao do Discord: via RPC, app comum so publica como
      "Jogando". O type enviado e ignorado.

Botoes de link nao aparecem:
    - botoes nunca aparecem para voce mesmo, apenas para quem ve o seu
      perfil. Peca para alguem conferir.

Musica/video sem barra de tempo:
    - o Firefox as vezes nao publica a posicao nem a duracao. Quando a
      posicao e desconhecida o daemon prefere nao mostrar tempo a
      mostrar tempo errado. Trocar de faixa costuma resolver.
    - o Stremio nunca publica posicao: nele o tempo conta desde que o
      titulo comecou.

Presenca "presa", de algo que ja fechei:
    - o Discord mantem a ultima atividade publicada mesmo depois que a
      conexao morre. Por isso o daemon apaga as presencas ao iniciar e
      ao ser encerrado. Se sobrar alguma coisa presa, basta:
        systemctl --user restart discord-game-presence
    - so precisa reiniciar o cliente se nem isso resolver:
        pkill vesktop && setsid vesktop >/dev/null 2>&1 &


--------------------------------------------------------------------
PASSO 13 - DESINSTALAR
--------------------------------------------------------------------
    systemctl --user disable --now discord-game-presence
    rm ~/.local/bin/discord-game-presence.py
    rm ~/.config/systemd/user/discord-game-presence.service
    rm -f ~/.config/discord-game-presence.json
    systemctl --user daemon-reload
